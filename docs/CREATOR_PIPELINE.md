# 크리에이터 발굴 파이프라인 (지원 접수 → 인터뷰 → 협업)

> 라운디의 첫 단계: 부담 없이 지원받고, 운영팀이 전화 인터뷰로 그 사람만의 고유성을 찾는다. (2026-11-26 구현)

## 흐름
1. **지원 접수** — `/apply` (로그인 없이, 1분). 필수 5개 + 연락처·동의, 선택 2개
2. **관리자 확인** — `/admin/creators` (신규 지원 목록 → 상세 → 상태 변경 → 인터뷰 메모)
3. **협업 진행** — 상태를 "협업 진행"으로 바꾼 뒤, 정식 호스트 신청(`/become-a-host/apply`, 로그인·계정 필요)으로 이어 감. 두 표는 일부러 분리

## 데이터 (Supabase, 마이그레이션 `20261126000100_creator_applications.sql`)
| 표 | 내용 | 접근 |
|---|---|---|
| `creator_applications` | 지원 ID, 이름·활동명, 분야, 잘하는 것, 관련 경험, 지원 동기, 연락처, SNS 링크, 희망 활동, 지원 일시, 지원 상태 | 읽기: 관리자(2단계 인증)만 · 연락처 열은 표에서 읽기 불가 · 쓰기는 DB 함수로만 |
| `creator_application_notes` | 전화 인터뷰 메모·녹취록·기타 (지원자별 여러 건) | 읽기: 관리자만 · 쓰기: `admin_add_creator_application_note` |
| `creator_application_outputs` | AI 고유성 분석, 소개 문구, 브랜딩 방향, 프로그램 기획안 (**아직 쓰는 화면 없음, 구조만**) | 읽기: 관리자만 · 쓰기 경로는 AI 연결 때 전용 함수로 추가 |

- 지원 상태: 신규 지원(new) → 검토 중 → 전화 인터뷰 예정 → 인터뷰 완료 → 협업 진행 / 보류 / 거절. 처음은 항상 신규 지원
- 제출 함수 `submit_creator_application` (비로그인 가능): 입력 검증, 같은 번호로 진행 중인 지원이 있으면 중복 불가(거절된 지원은 재지원 가능), 한 시간 100건 넘으면 일시 제한, 화면에는 자동 입력 방지용 숨은 칸
- 연락처 열람: 기본은 가림(010-****-5678), 사유 5자 이상을 적어야 원문 · 열람 기록은 감사 기록에 남음
- 상태 변경은 감사 기록(`creator_application.status`)에 남음

## 향후 AI 연결 (이번에는 만들지 않음)
- 분석은 **지원자 1명 단위**로 실행: 입력 = 지원서 답변(`creator_applications`) + 인터뷰 메모·녹취록(`creator_application_notes`), 출력 = `creator_application_outputs` (kind: uniqueness_analysis / intro_copy / branding_direction / program_plan, source: ai|manual, model 기록)
- 지침서: `docs/ai/CREATOR_ARCHITECT.md`, 에이전트 `.claude/agents/ai-planning-lead.md`
- 외부 AI로 보내기 전에 개인정보처리방침·동의 문구 법률 검토 필요 (동의 문구에는 "AI 도구로 분석할 수 있다"는 임시 문장이 들어 있음). 연락처는 AI 입력에서 제외할 것

## 알려진 한계·남은 일
- 지원서 개인정보 보관 기간 자동 정리(기존 호스트 지원서의 1년 정리처럼)는 아직 없음 → 법률 검토(L2) 결과에 맞춰 추가
- 정식 호스트 신청으로 자동 이전하는 기능은 없음(운영자가 안내). 필요해지면 "협업 진행 → 초대 링크" 기능 추가
