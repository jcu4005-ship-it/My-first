## 확인했지만 문제없던 것
- 자리 초과 신청: 신청 함수가 일정 행을 잠가 동시 신청에도 정원을 넘지 않음
- 권한: 모든 서버 동작이 로그인·관리자 확인을 거침, 표 접근은 RLS 이중 확인(pgTAP 572)
- 주입 공격 흔적(`dangerouslySetInnerHTML`, `eval`): 없음, 사용자 입력 링크는 https만 허용
- 의존성 보안 점검(`npm audit`): 취약점 0
- 돈 계산: 쿠폰은 최대 10%·가격 상한 100만 원·정수 넘침 없음, 환불은 한국 날짜 기준 3일 전 100% / 1~2일 전 50% / 당일 0%
- 신청: 시작했거나 지난 일정·열림 전 일정·중복 신청·본인 모임은 막힘, 취소 후 재신청 가능(중복 금지는 "진행 중"인 것만)
- 업로드: 이미지 3종(jpeg/png/webp)·5MB를 서버(스토리지)가 직접 제한
- 닉네임: 정규화한 키로 중복·예약어 차단 / 보안 헤더: 화면 감싸기 차단·HTTPS 강제·MIME 추측 방지 적용
- 예약 작업 4개(자리 해제·오픈 알림·후기 요청·일정 알림)가 매분/매시 정상 실행
- 모든 공개 화면 43개를 320px·375px에서 열어 콘솔 오류·깨진 이미지·가로 넘침 없음 / 로그인 상태(참가자·호스트·관리자) 화면도 동일 점검

## 알아 둘 점 (고치지 않았지만 기록)
- **쿠폰 "소진 한도" 경합**: 마지막 1장 남은 쿠폰을 서로 다른 일정에서 정확히 같은 순간에 쓰면 한도를 1~2장 넘길 수 있음 (자리 정원과 달리 쿠폰 행은 잠그지 않음). 영향은 할인 1~2건이라 낮음 — 쿠폰을 대량 운영하게 되면 쿠폰 행 잠금으로 보강
- **지원 접수 도배**: 로그인 없이 되므로 한 사람이 시간당 100건 한도를 채우면 정상 지원자가 잠시 막힘. 숨은 입력칸·전화번호 중복 방지는 있음. 문제가 생기면 접수 전 봇 확인(Turnstile 등) 추가
- **보안 정책 헤더(CSP)** 는 아직 없음: 다른 보안 헤더는 있음. CSP는 카카오·분석 도구와 충돌하기 쉬워 출시 전 별도로 시험 권장
- 소개 화면 상단 띠의 "SEOUL · YONGSAN" 은 잡지 컨셉의 장식 문구 — 사업장 소재지(마포구)와 다름. 의도한 표현인지 대표 확인 필요
- **폰 하단 메뉴에는 "열리는 원·크리에이터·저널·크리에이터 지원"이 없음**: 폰 방문자는 홈 하단 안내·푸터로만 크리에이터 지원에 도달. 크리에이터 모집이 핵심이면 폰 머리글에 "크리에이터 지원" 진입점을 추가하는 것을 권장(디자인 결정이라 대표 확인 후 진행)
