# 제품 구현 현황 (2026-11-05)

## 실제로 동작하는 흐름 (로컬·CI의 실제 DB로 검증)
```
회원가입·이메일 인증 → 호스트 신청 → 관리자 승인(2단계 인증)
→ 호스트: 모임 작성 → 일정 추가(정원·상세 주소) → 검수 요청
→ 관리자: 승인·공개 (또는 반려 사유 전달)
→ 참가자: 목록·상세에서 일정·인원 선택 → 신청 즉시 확정 → 신청 내역에서 상세 주소 확인 → 취소
→ 호스트: 일정별 신청 인원·참가자 닉네임 확인, 정원 변경·모집 마감·재개·일정 취소, 모집 종료
```

## 페이지
| 주소 | 대상 | 기능 |
|---|---|---|
| `/`, `/meetups`, `/meetups/[id]`, `/hosts/[id]` | 누구나 | 소개, 목록·카테고리, 상세(일정·남은 자리·신청), 호스트 프로필 |
| `/signup`, `/login`, `/forgot-password`, `/reset-password` | 누구나 | 이메일 가입·인증·로그인·재설정 |
| `/me` | 회원 | 프로필·연락처, 신청 내역·호스트 신청 바로가기, 로그아웃 |
| `/me/bookings` | 회원 | 다가오는 모임(상세 주소), 지난·취소 내역, 신청 취소 |
| `/host/apply` | 회원 | 호스트 신청, 심사 상태, 반려 사유·재신청 |
| `/host` | 승인된 호스트 | 내 모임 목록(상태·다음 일정·신청 현황) |
| `/host/meetups/new`, `/host/meetups/[id]/edit` | 승인된 호스트 | 모임 작성·수정 |
| `/host/meetups/[id]` | 승인된 호스트 | 검수 요청·취소, 모집 종료, 일정 추가·정원 변경·마감·취소, 참가자 |
| `/admin` | 관리자(2단계 인증) | 검수 대기 모임·심사 대기 호스트·공개 중 실제 모임 수 |
| `/admin/hosts` | 관리자 | 호스트 승인·반려(사유) |
| `/admin/meetups` | 관리자 | 모임 승인·공개·반려·운영 정지·재공개 |
| `/admin/members`, `/admin/audit` | 관리자 | 회원 역할·정지, 감사 기록 |

## 규칙 (DB가 최종 보장)
- 정원 초과·같은 일정 중복 신청 불가 (동시 신청 8건 → 정원 3건만 확정 검증)
- 1회 신청 인원: 모임별 1~4명
- 샘플 모임·내가 연 모임·공개 전 모임·지난 일정은 신청 불가
- 상세 주소는 확정 참가자와 호스트에게만
- 호스트는 참가자 연락처를 볼 수 없음 (닉네임·인원만)
- 확정 신청이 있으면 참가비 변경 불가, 신청자 있는 일정은 호스트가 취소 불가(운영팀 문의)
- 공개·반려·정지·호스트 승인은 관리자만, 모두 감사 기록
- 주류 모임은 공개·검수 요청 불가

## 아직 없는 기능
1. 결제(테스트 모드)·환불 — 현재 신청 즉시 확정, 참가비는 안내만
2. 알림(신청 확정·취소·일정 변경 메일), 호스트 공지
3. 모임 사진 업로드 (현재 카테고리별 디자인 표지)
4. 후기·저장·팔로우, 검색·지역 필터
5. 호스트가 신청자 있는 일정을 취소할 때의 일괄 취소·안내 (현재 운영팀 처리)
6. 회원 탈퇴 (출시 전 필수, LAUNCH_BLOCKERS)

## 알려진 제한
- 권한 없는 화면·없는 모임 주소는 "접근 권한 없음/찾을 수 없음" 화면과 검색 비노출 표시가 나오지만 HTTP 상태는 200일 수 있음 (Next.js 화면 틀 선전송). 보호된 내용은 노출되지 않음을 화면 테스트로 확인
- 샘플 데이터는 로컬·CI 전용. 스테이징은 "Deploy DB to staging" 실행 시 `seed_samples=yes`를 선택하고 승인해야 들어감 (운영 프로젝트와 같으면 중단)
