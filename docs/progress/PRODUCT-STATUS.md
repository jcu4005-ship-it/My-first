# 제품 구현 현황 (2026-11-06)

## 실제로 동작하는 흐름 (로컬·CI의 실제 DB로 자동 검증)
```
가입·이메일 인증 → 호스트 신청 → 관리자 승인(2단계 인증) → 모임 작성·일정 추가 → 검수 요청 → 관리자 공개
→ 참가자 신청 → (유료) 10분간 자리 확보 + 테스트 결제 → 확정, 상세 주소 공개, 호스트·참가자 알림
→ 참가자 취소 시 전액 환불(테스트) / 호스트 일정·모임 취소 시 신청자 전원 환불·알림
→ 회원 탈퇴: 비밀번호 재확인 → 예정 신청 취소·환불 → 개인정보 삭제·익명화 → 로그인 차단
```

## 페이지 추가분
| 주소 | 기능 |
|---|---|
| `/checkout/[bookingId]` | 테스트 결제 (실제 청구 없음, "테스트 결제" 표시), 결제 대기 취소 |
| `/me/notifications` | 알림 목록, 모두 읽음 (상단 메뉴에 안 읽은 수 표시) |
| `/me/withdraw` | 회원 탈퇴 |
| `/host/meetups/[id]` | 일정 취소(사유·환불·알림), 모임 전체 취소 추가 |

## 결제 (테스트 모드)
- 결제사 연결부: `src/lib/payments/provider.ts` — 현재 **모의 결제(mock)** 만 존재. 토스페이먼츠 테스트 키 발급 후 같은 구조로 추가
- 금액은 화면에서 받지 않고 DB에서 계산, 결제 확정·환불 기록은 서버 비밀키로만 (참가자가 직접 호출 불가 — 테스트로 확인)
- DB 제약으로 `mode = 'live'` 결제 기록 자체가 불가, 환경변수 검증으로 live 모드 빌드 불가
- 환불 규정(기한별 비율)은 아직 미적용: 시작 전 취소는 전액 환불

## HTTP 상태
- 요청 전처리(`src/proxy.ts`)에서 화면 생성 전 확인: 권한 없음 403, 없는·비공개 대상 404, 비로그인 로그인 화면 이동, 관리자 2단계 인증 전 인증 화면 이동
- 화면(guards)·DB(RLS·함수) 검사는 그대로 유지

## 아직 없는 기능
1. 토스페이먼츠 테스트 결제 연동(키 필요), 기한별 환불 규정, 정산
2. 이메일 알림 (현재 사이트 내 알림만. 실제 사용자 메일 발송은 발송 서비스·승인 필요)
3. 모임 사진 업로드, 후기·저장·팔로우, 지역·날짜 검색
