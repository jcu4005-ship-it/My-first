# 기능 명세: 호스트 정책 · 로드맵 (2026-11-06)

> 사업 계획(`docs/BUSINESS_PLAN.md` v1.1)의 호스트 정책과 로드맵을 **제품 기능 목록**으로 옮긴 문서.
> 상태: ✅ 구현됨(스테이징 검증) / 🟡 일부 / ⬜ 미구현
> DB: 기존 테이블·열은 지우거나 바꾸지 않고, 필요한 것은 **추가 마이그레이션 + RLS + pgTAP 테스트**로 만든다 (창업자 승인 후).

## A. 호스트 정책 → 기능

### A-1. 입장·심사
| ID | 정책 | 기능 | 상태 | DB |
|---|---|---|---|---|
| H-01 | 입장료 없음 | 호스트 신청 무료, 결제 단계 없음 | ✅ | — |
| H-02 | 경력 심사 | 신청서: 경력(필수 20자+), 자격·수상, 포트폴리오(https), 가르친 경험 / 관리자 승인·반려(사유) | ✅ | — |
| H-03 | 호스트 정책 안내 | 호스트 안내 페이지 `/for-hosts` (수수료 구조, 심사 기준, 정산, 지켜야 할 것, 앞으로의 계획) | ✅ (이번 작업) | — |
| H-04 | 호스트 유형 | Expert / Creator / Community Host 배지 (프로필·카드·상세) + 관리자 지정 | ⬜ | `host_profiles.host_type` 추가 |

### A-2. 수익·수수료
| ID | 정책 | 기능 | 상태 | DB |
|---|---|---|---|---|
| H-10 | 판매될 때만 수수료 | 결제 시점 수수료율 스냅샷, 정산 금액 계산 | 🟡 설계만 (테스트 결제는 있음, 수수료 계산 없음) | `commission_tiers`, `bookings.commission_rate_snapshot` 등 |

| H-13 | 단골 재수강 수수료 인하 | 같은 호스트 클래스 재신청 자동 판별 → 인하 | ⬜ | 기존 bookings로 계산 + 스냅샷 |

| H-17 | Host Pro (나중) | 월 구독으로 수수료 인하·노출 우선 | ⬜ (후순위) | — |

## D. 로드맵 → 개발 순서

| 단계 | 사업 단계 | 개발 항목 | 비고 |
|---|---|---|---|
| 0 | 브랜드 (이름·목소리·사진) | 브랜드 설정 교체, 사진 넣기 | 이름 확정 시 `brand.ts` 한 곳 |
| 1 | 파일럿 호스트 5명 (지인) | **H-03 호스트 안내 페이지** ✅, H-04 유형 배지 | 지인도 같은 심사 기준 |
| 2 | 실결제 전환 | 토스 연동, H-10·H-14 수수료·PG 기록, 약관·환불 규정 | 계약·법률 선행 |
| 3 | 공개 클래스 운영·측정 | **M-01 출석 → M-02 후기 → D-01 설문 → D-02 지표** | 파일럿 지표 측정의 전제 |
| 4 | Founding Member 100명 | F-01·F-02·F-09, F-03·F-04·F-05 | 클래스 수 충분할 때 |
| 5 | 팬덤 확장 | F-06 Originals, F-07 등급, F-08 초대권, H-12·H-13 추천·단골 수수료 | |
| 6 | 정산 운영 | H-11·H-15·H-16 | 첫 정산 전 필수 |
| 7 | 호스트 육성 | M-03·M-04, H-05 | 첫 Community Host |
| 8 | 수익 다각화 | P-01 유료 기획 패키지, H-17 Host Pro | 법률 검토 후 |
| 9 | 문화·예술 확장 | 비활성 카테고리 재개 (클래스 형식), 새 카테고리 | 데이터 보존되어 있음 |

**지금 바로 할 수 있는 다음 개발 (추천):** 3단계의 **M-01 출석 체크 → M-02 후기** — 파일럿 측정과 락인(H-22), 멤버십 자격(F-01), 등급(F-07)이 모두 이것에 기대고 있다.
